# Правила проекта NotchIsland

## Не дублировать то, что уже есть

Прежде чем предлагать или добавлять функцию, проверь, не делает ли то же самое macOS, iOS
или сам NotchIsland. Если делает, функцию не добавляем: два пути к одному результату
создают кашу в интерфейсе и в коде.

- Новое оправдано только тогда, когда даёт то, чего у существующего нет. Например, Portal
  отличается от AirDrop эффектом пета, миниатюрой у выреза и жестом смахивания в своём
  приложении.
- Если идея повторяет системную функцию, например Portal через меню «Поделиться» повторяет
  AirDrop, сразу так и скажи и не предлагай её как вариант.
- Лучше улучшить то, что уже есть, чем добавить рядом ещё одну кнопку, настройку или эффект с
  тем же смыслом.

## Команды

| Что | Команда |
|---|---|
| Сборка (проверить, что компилируется) | `swift build` |
| Тесты | `swift test` |
| Собрать, поставить в /Applications и перезапустить | `./build.sh --install` |
| DMG для других (universal) | `./package.sh` → `dist/NotchIsland.dmg` |
| Релиз (версия, тег, GitHub Release, appcast) | `./release.sh <версия> "<что нового>"`, пробный прогон — `--dry` |
| iOS-компаньон | `cd PortalCompanion && xcodegen` после добавления файлов, дальше Xcode |

- Пользователь запускает приложение из /Applications: `swift build` ничего не меняет на экране.
  После правок интерфейса — `./build.sh --install`, и только потом «готово».
- Сохранённые настройки (UserDefaults) важнее новых значений по умолчанию: если новое значение
  по умолчанию должно стать видно, выставь его через `defaults write`.
- `./release.sh` публикует для всех и сам коммитит и пушит — запускать только по прямой просьбе.

## Как устроен код

- `Sources/NotchIslandCore` — логика без интерфейса, покрыта тестами в `Tests/NotchIslandCoreTests`.
  Новую логику, которую можно отделить от UI, клади сюда и пиши к ней тест.
- `Sources/NotchIsland` — приложение (AppKit + SwiftUI + Core Animation).
- `Sources/notchisland-hook`, `Sources/notchisland-cli` — вспомогательные программы внутри .app.
- `Helper/NowPlayingBridge.m` — мост к системному Now Playing, собирается `build.sh`.
- `docs/` — описание форматов и подсистем (Developer Mode, Portal).
- Единственная зависимость — Sparkle. Новые зависимости не добавляем без явного согласия.

## Как работаем

- Одна задача — одна ветка — один PR. В `main` напрямую не коммитим.
- Перед PR: `swift build` и `swift test` проходят. CI (`.github/workflows/ci.yml`) проверяет то же
  самое на каждый PR; красный CI — не сливаем.
- Баг: сначала тест, который его воспроизводит (если логика в `NotchIslandCore`), потом исправление.
  Один баг — один коммит.
- Бэклог — `TODO.md`. Новые находки записываем туда с путём и строкой, исправленное отмечаем `[x]`.
- Если по ходу задачи всплыла другая — не делаем её в этой ветке, а записываем в `TODO.md`.
- Сообщения коммитов — по-английски, коротко, в стиле истории: «Portal: pair an iPhone by …».
