# Portal: фото и файлы с iPhone на Mac

Смахиваешь фото на iPhone, и оно «перелетает» на Mac: у правого края экрана играет эффект, у выреза
появляется миниатюра (клик открывает файл), а сам файл ложится в «Загрузки» или в папку из настроек.

Включается в **Настройки NotchIsland → Portal**. По умолчанию выключено: при включении macOS спросит
доступ к локальной сети.

| Что | Где |
|---|---|
| Приём (Multipeer, `_notch-portal._tcp`) | `Sources/NotchIsland/Portal.swift` |
| HTTP `POST /upload` для «Быстрых команд» | там же, `PortalHTTPServer` |
| Разбор HTTP и multipart, имена файлов, токен (с тестами) | `Sources/NotchIslandCore/Portal.swift` |
| Эффекты у края экрана: «Радуга», «Портал», «Волны» | `Sources/NotchIsland/PortalEffects.swift` |
| Настройки | `Sources/NotchIsland/PortalSettings.swift` |
| iOS-компаньон | `PortalCompanion/` |

Посмотреть эффекты без iPhone: кнопка **«Показать»** в настройках или офлайн-кадры:

```bash
swift build && .build/debug/NotchIsland --capture-portal /tmp/portal-frames
```

## Способ 1. Приложение PortalCompanion на iPhone

Сетка фото и файлов. Карточку нужно резко смахнуть вправо (быстрее ~900 pt/с или достаточно далеко).
Тогда она улетает, iPhone даёт отклик вибрацией, а файл уходит на Mac через `sendResource`. Если отправка
не удалась, карточка возвращается на место.

### Установка на свой iPhone с бесплатным Apple ID

1. Открой `PortalCompanion/PortalCompanion.xcodeproj` в Xcode.
2. **Xcode → Settings → Accounts → +**, войди своим Apple ID. Появится команда «… (Personal Team)».
3. Выбери цель **PortalCompanion → Signing & Capabilities**. Поставь галочку *Automatically manage signing*
   и выбери Team = свою Personal Team.
4. Если Xcode пишет, что bundle identifier занят, поменяй `local.notchisland.portalcompanion` на свой
   уникальный, например `com.<твоё-имя>.portal`.
5. Подключи iPhone кабелем (или по Wi-Fi после первого раза). На iPhone включи
   **Настройки → Конфиденциальность и безопасность → Режим разработчика** и перезагрузи телефон.
6. Выбери iPhone в списке устройств вверху Xcode и нажми **Run (⌘R)**.
7. При первом запуске iPhone скажет «Ненадёжный разработчик». Открой **Настройки → Основные → VPN и
   управление устройством**, выбери свой Apple ID и нажми «Доверять».
8. Разреши приложению доступ к локальной сети.

Подпись бесплатным Apple ID действует **7 дней**. Потом приложение перестанёт открываться, и его нужно
снова запустить из Xcode (⌘R). Данные при этом сохраняются.

Если ты добавлял файлы в папку, перегенерируй проект: `cd PortalCompanion && xcodegen`
(`brew install xcodegen`). Сам `.xcodeproj` лежит в репозитории, поэтому для сборки xcodegen не нужен.

### Первое подключение

1. На Mac: Настройки → Portal → «Принимать файлы с iPhone».
2. На iPhone откроется Portal. Если рядом один Mac, приложение подключится к нему само, если несколько, нажми «Mac».
3. Сопряжение. Под вырезом Mac появится окно «Подключить „iPhone“?» с шестизначным кодом, на iPhone тот же
   код. Сверь их: если совпадают, нажми «Совпадает» на iPhone и «Коды совпадают» на Mac (порядок любой).
   Если коды разные, кто-то пытается встать посередине, жми «Отклонить».
4. После этого телефон и Mac хранят общий ключ в связке ключей, и следующие подключения проходят молча.
   Отозвать доступ можно в Настройки → Portal → Устройства → «Забыть»: телефон сразу перестанет
   отправлять, а при следующем подключении попросит сопряжение заново.

iOS не сообщает приложениям настоящее имя телефона, поэтому имя по умолчанию — просто «iPhone».
Своё имя задаётся в Portal → ⚙︎. Имя только подпись: Mac узнаёт телефон по ключу.

## Способ 2. «Быстрые команды» без приложения

Этот способ работает из меню «Поделиться» в любом приложении. Нужно, чтобы iPhone и Mac были в одной сети Wi-Fi.

### На Mac

Настройки NotchIsland → Portal → **«Принимать из „Быстрых команд“ (HTTP)»**. Ниже появятся:

- адрес, например `http://MacBook-Ivan.local:54321/upload` (и вариант с IP);
- **токен** (кнопка 👁 показывает его, ⧉ копирует).

Проверка с самого Mac:

```bash
curl http://127.0.0.1:54321/
```

```bash
curl -X POST --data-binary @photo.heic -H "Authorization: Bearer ТОКЕН" -H "X-Filename: photo.heic" http://127.0.0.1:54321/upload
```

### На iPhone: команда «Отправить в NotchIsland»

1. Открой **Команды → +** и назови команду «Отправить в NotchIsland».
2. Нажми **ⓘ** (Сведения) и включи **«Показывать в меню „Поделиться“»**. Типы: *Изображения, Медиа, Файлы*
   (можно «Любой»). Если на входе ничего нет, выбери «Запрашивать: Фото».
3. Добавь действие **«Повторить с каждым»** с входом *Ввод из быстрой команды*.
4. Внутри повтора добавь **«Получить содержимое URL»**:
   - URL: адрес из настроек Mac, например `http://MacBook-Ivan.local:54321/upload`;
   - Метод: **POST**;
   - Заголовки:
     - `Authorization` → `Bearer ТОКЕН`
     - `X-Filename` → переменная *Повторяемый объект → Имя* (с расширением; если расширения нет,
       Mac подставит его по типу файла);
     - по желанию `X-Device-Name` → `iPhone Ивана` (покажется в «чёлке»);
   - Текст запроса: **Файл**, значение: *Повторяемый объект*.
5. Можно добавить после повтора **«Показать уведомление»** с текстом «Улетело на Mac ✨».

Вариант «Текст запроса: Форма» (поле `file` типа «Файл») тоже работает, тогда Mac сам вырежет файл
из multipart.

При первом запуске iPhone спросит разрешение на доступ к локальной сети. Нажми «Разрешить».

**Если не работает:**

- `wrong token`: токен в команде не совпадает с токеном на Mac (после «Новый» его надо вставить заново).
- Нет ответа: проверь, что iPhone в той же Wi-Fi, что и Mac. Попробуй адрес с IP вместо `.local`.
  При первом запуске macOS может спросить, разрешить ли NotchIsland входящие подключения. Нажми «Разрешить».
- Большие видео идут долго: файл передаётся по Wi-Fi целиком, лимит 8 ГБ.

### Безопасность

- HTTP без шифрования, только в локальной сети. Токен защищает от случайных отправителей, но не от
  того, кто подслушивает твою Wi-Fi. В чужих сетях держи HTTP выключенным.
- Multipeer шифруется (`encryptionPreference: .required`), но сам по себе не знает, с кем говорит.
  Поэтому поверх него сопряжение (`Sources/NotchIslandCore/PortalPairing.swift`, общий для Mac и iPhone):
  - первое подключение: обмен ключами X25519 с предварительным обязательством (commitment) и
    шестизначный код из общего секрета на обоих экранах, как сравнение чисел в Bluetooth. Посредник
    получил бы разные коды на Mac и iPhone;
  - дальше каждое подключение — HMAC-SHA256 по свежим случайным числам в обе стороны: Mac принимает
    файлы только от телефона с ключом, а телефон отправляет только Mac, который доказал, что знает ключ.
    Подделанное имя ничего не даёт;
  - ключи лежат в связке ключей, только на этом устройстве (`AfterFirstUnlockThisDeviceOnly`);
  - файл от непроверенного телефона отменяется в самом начале и не сохраняется.
- Старые разрешения «по имени» после обновления сброшены: каждый iPhone один раз проходит сопряжение.
